### 学新知识

**1. 先回忆一下：第 5 周你用过的 Pydantic 是什么**

```python
from pydantic import BaseModel

class Todo(BaseModel):
    title: str
    done: bool = False
```

就是在 FastAPI 里用来"规范请求体"的。但它其实比这强得多。

**2. Pydantic v2 核心能力（本周只学最实用的 4 个）**

| 能力 | 说明 | 例子 | 面试高频 |
|---|---|---|---|
| 字段类型校验 | 自动检查类型，不对返回 422 | `title: int` 传了字符串 → FastAPI 自动返回 422 | ⭐⭐⭐⭐⭐ |
| 默认值 + 可选 | `field: str = None` 或 `field: Optional[str] = None` | 注册时邮箱可以不填 | ⭐⭐⭐⭐ |
| 模型继承 | 公共字段抽到基类，子类继承 | UserBase → UserCreate（注册用）/ UserLogin（登录用） | ⭐⭐⭐⭐ |
| 自动类型转换 | 字符串数字自动转 int | `"123"` → `123` | ⭐⭐ |

**3. 模型继承（注册 vs 登录 vs 数据库存储，用不同模型）**

这是 Pydantic 最实用的设计模式——**一个接口场景对应一个 Pydantic 模型，不要一个模型用到底**：

```python
from pydantic import BaseModel
from typing import Optional

# 基类：公共字段
class UserBase(BaseModel):
    username: str

# 注册用：注册必须有密码
class UserCreate(UserBase):
    password: str
    email: Optional[str] = None

# 登录用：登录只需要用户名 + 密码
class UserLogin(UserBase):
    password: str

# 数据库存储用：存进去的东西和请求来的不一样
class UserInDB(UserBase):
    id: int
    hashed_password: str  # 注意：存的是加密后的，不是明文
    email: Optional[str] = None
```

> 为什么要这么分？因为注册、登录、数据库存的东西不一样。注册要传密码但不需要 id（id 数据库自动生成）；数据库存的密码是加密的，不能返回给前端。这是 FastAPI 项目最基本的"安全意识"。

**4. Pydantic 校验失败会发生什么**

FastAPI 自动返回 **422 Unprocessable Entity**，响应体里有详细的哪个字段错了、为什么错。面试高频问"FastAPI 参数校验失败返回什么状态码"，答 422 就对了。

### 【MySQL 铺垫】今天的 Pydantic 模型 → 第 7 周的 MySQL 表

今天的 UserBase 有 `username: str`，UserInDB 有 `id: int`、`hashed_password: str`、`email: Optional[str]`。第 7 周换成 MySQL 时，对应的数据库表大概长这样：

```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    hashed_password VARCHAR(255) NOT NULL,
    email VARCHAR(100),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

Pydantic 模型 = "我要什么"；MySQL 表 = "实际存什么"。两者长得有点像但不一样，因为数据库有主键、自增、默认值等约束。知道大概就行，具体第 7 周再练。

### 学新知识

**1. 为什么要路由分层**

第 5 周的待办 API 只有 5 个接口，一个文件搞定。但如果有用户模块（注册、登录、个人信息、修改密码...）、待办模块（CRUD）、商品模块、订单模块... 一个文件里 30+ 个接口会很乱。

**解决：APIRouter** —— 每个模块一个文件，各自负责各自的接口，最后在主 app 里统一导入。

**2. APIRouter 基本用法**

```python
# routers/users.py（用户模块）
from fastapi import APIRouter

router = APIRouter(prefix="/users", tags=["用户"])

@router.post("/register")
def register():
    return {"message": "注册"}

@router.post("/login")
def login():
    return {"message": "登录"}
```

```python
# routers/todos.py（待办模块）
from fastapi import APIRouter

router = APIRouter(prefix="/todos", tags=["待办"])

@router.get("/")
def list_todos():
    return []
```

```python
# main.py（主文件）
from fastapi import FastAPI
from routers import users, todos

app = FastAPI()
app.include_router(users.router)
app.include_router(todos.router)
```

### 学新知识

**1. 密码加密（安全意识）**

真实项目里**绝对不能把用户密码明文存进数据库**。要用哈希库加密：

```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 注册时：把明文密码加密再存
hashed_password = pwd_context.hash("用户输入的明文密码")

# 登录时：验证用户输入的密码对不对
is_valid = pwd_context.verify("用户输入的密码", hashed_password)
```

> 2026 优化版说明：bcrypt 需要 C++ 编译环境，Windows 上如果装不了，可以先用 `hashlib` 做简单哈希（`hashlib.sha256(password.encode()).hexdigest()`），等环境弄好再切 bcrypt。面试时说"我知道密码要哈希，用 bcrypt"就行。

**2. 用户名查重**

注册时要检查用户名是否已存在：
- 用内存列表存用户时：`any(u["username"] == username for u in users_db)`
- 第 7 周换 MySQL 时：`db.query(User).filter(User.username == username).first()`

### 动手写代码

在 `routers/users.py` 里填完整的注册逻辑：

```python
# 内存模拟数据库
users_db = []  # [{username, hashed_password, email, id}, ...]

@router.post("/register", response_model=UserBase)
def register(user: UserCreate):
    # 1. 用户名查重
    if any(u["username"] == user.username for u in users_db):
        raise HTTPException(status_code=400, detail="用户名已存在")
    
    # 2. 密码加密（先用 hashlib 简单版）
    hashed = hashlib.sha256(user.password.encode()).hexdigest()
    
    # 3. 生成新 id
    new_id = len(users_db) + 1
    
    # 4. 存进去
    user_in_db = {
        "id": new_id,
        "username": user.username,
        "hashed_password": hashed,
        "email": user.email,
    }
    users_db.append(user_in_db)
    
    # 5. 返回给前端（只返回 username，不返回密码！）
    return {"id": new_id, "username": user.username}
```

> 2026 优化版常见坑：写 `raise HTTPException` 之前要 `from fastapi import HTTPException`；如果返回 UserBase 而 UserBase 没有 id 字段但你返回了 `{"id": new_id, "username": user.username}`，FastAPI 会自动过滤掉 UserBase 里没有的字段——这正是 Pydantic `response_model` 的作用：**控制返回给前端哪些字段**（密码绝对不能返回）。

### 学新知识

**1. 登录验证逻辑（和注册对应）**

```python
@router.post("/login")
def login(user: UserLogin):
    # 1. 在内存数据库里找这个用户
    found = next((u for u in users_db if u["username"] == user.username), None)
    
    # 2. 没找到 → 返回 401 未授权
    if not found:
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    
    # 3. 找到 → 验证密码（加密后的 hash 对不对）
    if not pwd_context.verify(user.password, found["hashed_password"]):
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    
    # 4. 登录成功 → 返回 token（今天可以先返回固定字符串，明天或下周换 JWT）
    return {"message": "登录成功", "username": user.username}
```

**2. 可选挑战：JWT 是什么（能跳过）**

JWT（JSON Web Token）是一种"身份凭证"。登录成功后服务器生成一个 token 返回给前端，前端以后每次请求都带上这个 token，服务器就能知道"这个用户已经登录过了"。

- 安装：`pip install python-jose[cryptography] passlib[bcrypt] -i https://pypi.tuna.tsinghua.edu.cn/simple`
- 生成 token：给 payload 加用户名和过期时间 → 用密钥签名
- 验证 token：每个需要登录才能访问的接口，加一个依赖把 token 解出来

> **2026 优化版建议**：JWT 理解成本不低，第 7 周之前时间有限的话**可以跳过**——先保注册/登录能返回成功/失败，简历上也能说"熟悉用户认证的基本流程，可根据需要扩展 JWT"。如果时间充裕想练，周五下午可以花 2 小时搞。

### 【MySQL 铺垫】登录验证的数据库查询

今天：`found = next((u for u in users_db if u["username"] == user.username), None)`
第 7 周：`found = db.query(User).filter(User.username == user.username).first()`
（语法完全一样，只是数据源从内存列表换成了 SQLAlchemy 查询，几乎不用改业务逻辑）
