> 测试时也要注意：故意传错类型、故意少传字段、故意传空字符串，看 FastAPI 会不会正确返回 422。

# 周三（11 月 18 日）：用户注册模块（简单版 · 不带 JWT）+ README 启动
> 给注册接口设计"正常 + 异常"测试点：
> - 正常：传入合法的 username + password → 注册成功，返回 200  
username:"aaa"  
password:"qwe123!@#"
> - 异常：传入空 username → FastAPI 返回 422  
username:""  
password:"qwe123!@#"
> - 异常：传入空 password → FastAPI 返回 422  
username:"aaa"  
password:""
> - 异常：已存在的 username → 我们自己 raise 400
> - 异常：password 太短（比如传 1 个字符）→ 如果没做长度校验，我们自己的代码会不会被绕过？  
加入长度校验  
> - 边界：密码全是数字/密码全是字母：密码复杂度低，不安全  
返回密码复杂度过低并让用户重新设置密码
