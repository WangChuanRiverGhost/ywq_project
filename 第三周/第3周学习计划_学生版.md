## 周一（10月26日）：函数是"一等公民" + 闭包

### 今日重点
- 搞懂一个关键认知：**函数也是对象**，可以赋给变量、当参数传、当返回值返回。
- 理解**闭包**——这是装饰器的"地基"，闭包懂了装饰器就懂了一大半。

### 学新知识

**1. 函数是一等公民**
```python
def greet(name):
    return f"你好，{name}"

f = greet            # ① 函数可以赋给变量
print(f("小明"))     # 你好，小明

def run(func, x):    # ② 函数可以当参数传
    return func(x)
print(run(greet, "小红"))  # 你好，小红

def outer():         # ③ 函数可以当返回值返回
    def inner():
        return "我是内层函数"
    return inner
g = outer()
print(g())           # 我是内层函数
```

**2. 闭包（Closure）**
- 定义：**内层函数引用了外层函数的变量，外层函数返回这个内层函数**，这个"打包"了变量和函数的结构就叫闭包。
```python
def make_multiplier(n):
    def multiply(x):
        return x * n      # 内层函数用到了外层的 n
    return multiply

times3 = make_multiplier(3)
print(times3(5))          # 15
```
- 关键点：外层函数执行完后，变量 `n` **不会被销毁**，而是被内层函数"记住"了。

### 动手写代码（`day9_closure.py`）

1. 写一个 `make_counter()` 闭包：每次调用返回的数比上次大 1（计数器）
2. 写一个 `make_power(n)` 闭包：返回"计算 x 的 n 次方"的函数
3. 验证：`counter()` 连续调用三次，看结果是不是 1、2、3（体会"变量被记住了"）

### 测试思维训练（追加到 `测试思维.md`）

给 `make_counter` 写测试清单：
- 正常情况：第一次调用返回 1，第二次返回 2
- 边界情况：创建两个独立的计数器，互不影响
- 异常情况：闭包返回的是"函数"而不是"数字"，若直接 `print(make_counter())` 会打印出函数对象

## 周二（10月27日）：装饰器入门（无参数装饰器）

### 今日重点
- 理解装饰器的本质：**在不修改原函数代码的前提下，给函数"加功能"**。
- 掌握无参数装饰器的写法和 `@` 语法糖。

### 学新知识

**1. 装饰器 = 高阶函数 + 闭包**

先不写 `@`，手写"包装"过程：
```python
def my_decorator(func):
    def wrapper():
        print("函数执行前……")
        func()
        print("函数执行后……")
    return wrapper

def say_hello():
    print("你好！")

say_hello = my_decorator(say_hello)   # 手动包装
say_hello()
```

**2. 用 `@` 语法糖，上面等价于：**
```python
@my_decorator
def say_hello():
    print("你好！")
```
- `@my_decorator` 就相当于 `say_hello = my_decorator(say_hello)`，只是写得更简洁。

## 周三（10月28日）：装饰器进阶（functools.wraps + 带参数装饰器）

### 今日重点
- 认识一个坑：装饰器会"偷走"原函数的名字和文档，用 `functools.wraps` 修。
- 学会**带参数的装饰器**（三层嵌套）。

### 学新知识

**1. functools.wraps 修元信息**
```python
import functools

def my_decorator(func):
    @functools.wraps(func)     # 关键：保留原函数的名字/文档
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```
- 没有 `@functools.wraps` 时，`被装饰函数.__name__` 会变成 `"wrapper"`（名字丢了）。

**2. 带参数的装饰器（三层嵌套）**
```python
import functools

def repeat(times):                       # 第一层：接收装饰器参数
    def decorator(func):                 # 第二层：接收被装饰函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):    # 第三层：真正的包装
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(3)
def say_hi():
    print("hi")
# 调用 say_hi() 会打印 3 次 "hi"
```

## 周四（10月29日）：装饰器实战 + 上下文管理器入门

### 今日重点
- 把前两天的装饰器用到真实场景，尤其实现**参数校验装饰器**（呼应测试岗）。
- 认识 `with` 语句和上下文管理器的底层机制。

### 学新知识

**1. 参数校验装饰器（实用 + 呼应测试岗）**
```python
import functools

def check_positive(func):
    @functools.wraps(func)
    def wrapper(x):
        if x < 0:
            raise ValueError("参数不能是负数")
        return func(x)
    return wrapper

@check_positive
def sqrt(x):
    return x ** 0.5
```

**2. with 语句的底层：`__enter__` / `__exit__`**
```python
class MyContext:
    def __enter__(self):
        print("进入 with，做准备工作")
        return self
    def __exit__(self, exc_type, exc_val, exc_tb):
        print("退出 with，做清理工作（无论有没有异常都会执行）")

with MyContext():
    print("with 块里的代码")
```

## 周五（10月30日）：contextlib 简化上下文管理器 + Git 基础

### 今日重点
- 学会用 `@contextmanager` 一行行简化上下文管理器。
- 补齐 Git 原理：工作区 / 暂存区 / 版本库，常用命令。

### 学新知识

**1. @contextmanager 简化**
```python
from contextlib import contextmanager

@contextmanager
def timer():
    import time
    start = time.time()
    yield                       # yield 之前是 __enter__，之后是 __exit__
    print(f"耗时 {time.time() - start:.4f} 秒")

with timer():
    sum(range(1000000))
```

**2. Git 三个区 + 常用命令**
- 工作区（你的文件）→ `git add` → 暂存区 → `git commit` → 版本库
- 常用命令：`git init` / `git status` / `git add` / `git commit` / `git log` / `git diff`
