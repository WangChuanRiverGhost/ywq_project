# 生成器和迭代器的二次学习
### 1、可迭代对象、生成器和迭代器
可迭代对象是实现了iter( )方法的对象。如列表、元组、字符串、字典等；  
生成器必须是一个表达式，或者一个存在yield关键字的函数；  
迭代器必须是，由可迭代对象通过iter()创建而来，或者一个存在`__iter__`和`__next__`的对象。  
### 2、python的内置生成器/迭代器
```python
range(start, stop, step)
enumerate(iterable, start=0)
zip(*iterables)
map(function, iterable, ...)
filter(function, iterable)
reversed(sequence)
```
### 3、生成器和迭代器的创建
对于生成器来说，有两种创建生成器的方式：  
```python
# 将一个列表生成式的方括号改成圆括号
a = (i * i for i in range(1,5))
# 在一个函数中加入yield关键字
def print_hello():

    for i in range(1,5):
        yield i*i

a = print_hello()
```
其中，生成器遇到yield关键字会返回后面的数据并保存当前状态。  
对于迭代器来说，可以通过iter函数或类来创建迭代器：
```python
# 通过iter(可迭代对象)创建迭代器
a = iter("helo")
# 通过存在__iter__和__next__的类创建实例来创建迭代器对象
class aa:
    def __iter__(self):
        self.a = 1
        return self

    def __next__(self):

        if self.a <= 5:
            self.a += 1
            x = self.a
            return x
        else:
            raise StopIteration
b = iter(aa())
```
其中：  
`__iter__`是作为【初始化一个迭代器生命周期】以及【符合迭代器的语法规定】的角色出现；  
`__next__`则是【决定具体迭代逻辑】、【返回每次迭代结果】以及【抛出 raise StopIteration】。  
#### 关于`raise StopIteration`:  
在迭代器不是一个无限循环的迭代器的前提条件下，应当在`__next__`中添加`raise StopIteration`来在适当的位置截断`__next__`。如果没有重新初始化并且迭代器对象中的资源已迭代完毕，再次发起next( )只会继续抛出StopIteration错误。
### 4、生成器和迭代器的使用
在上述例子中，通过next( )分别调用生成器/迭代器对象：
```python
# 生成器
for i in range(1,6):
    print(next(a))  # 如果期望获取生成器的值，那么a是一个生成器对象。可以是表达式或者一个有yield关键字的函数对象
```
输出：
```text
1
4
9
16
Traceback (most recent call last):
  File "d:\实训\学习计划\第三周\作业代码\day13_contextlib.py", line 26, in <module>
    print(next(a))
          ~~~~^^^
StopIteration
```
此处报错是因为期望打印的next(a)的数据超出了实际上next(a)的生命周期的迭代次数，在实际代码中需要注意这个问题。  
（要使以上代码不报错只需要把for循环条件的range改成`range(1,5)`即可）
```python
# 迭代器
b = iter(aa())
for i in range(5):

    print(next(b))
b = iter(b)
for i in range(5):

    print(next(b))
```
输出：
```text
2
3
4
5
6
2
3
4
5
6
```
可以看到，迭代器进行了两次循环，而在第二层循环前，我们在代码中通过重新调用 `__iter__` 方法（内部将a重新赋值为 1）来重置状态,即【初始化一个迭代器生命周期】。  
#### 总结
生成器：表达式/存在yield关键字的函数 -> 创建生成器对象 -> 循环`next()`调用生成器对象  
迭代器：可迭代对象/存在`__iter__`和`__next__`函数的类 -> `iter()`创建迭代器对象 -> 循环`next()`调用生成器对象。  
# `@contextmanager`简化上下文管理器
本质上，`@contextmanager`是一个装饰器，我们需要传入一个生成器。  
`@contextmanager`可以简化一个完整的上下文管理器对象的构建，其原理是使用生成器的yield关键字，yield前的代码将在with时被调用（并返回值，即充当`__enter__`的作用）；yield执行后的代码将在with代码块结束后执行（即充当`__exit__`的作用）。  
从另一个角度讲，`@contextmanager`也可以将符合“只yield一次”规范的生成器，转化为上下文管理器对象。
```python
from contextlib import contextmanager

@contextmanager
def print_hello():
    print("hello")

    a = 11
        
    yield a
    print(f"返回值是{a}")

with print_hello() as b:
    print(b)
```
输出：
```text
hello
11
返回值是11
```
需要注意的是，虽然`@contextmanager`装饰器后面跟的是一个生成器，但其被装饰后实际上返回的是一个上下文管理器。  
所以，当使用`with...as...`时，as后的变量获得的引用不一定是生成器，不一定可以用with获取值，需要注意yield返回的对象类型。  
如示例：
```python
from contextlib import contextmanager

@contextmanager
def print_hello():
    print("hello")
    a = 11
    yield a
    print(f"返回值是{a}")
with print_hello() as b:
    
    print(next(b))
```
输出：
```text
hello
Traceback (most recent call last):
  File "d:\实训\学习计划\第三周\作业代码\day13_contextlib.py", line 14, in <module>
    print(next(b))
          ~~~~^^^
TypeError: 'int' object is not an iterator
```
背后的逻辑是，当我们试图用next( )去遍历一个int时，会报错。而在生成器被`@contextmanager`装饰后，python会把这个错误抛给yield。如果没有对yield进行异常处理，则相当于在上下文管理器对象的`__exit__`中返回False，直接抛出异常使程序崩溃。  
所以通常来讲，`@contextmanager`的生成器中需要对yield进行异常处理：
```python
from contextlib import contextmanager

@contextmanager
def print_hello():
    print("hello")
    a = 11
    try:
        yield a
    except:
        print("出错了")
    finally:
        print(f"返回值是{a}")

with print_hello() as b:
    
    print(next(b))
```
输出：
```text
hello
出错了
返回值是11
```
# git基础
### 1、git安装与配置
官网安装git：https://git-scm.com/install/windows  
配置姓名和邮箱：
```git
$ git config --global user.name "Your Name"
$ git config --global user.email "email@example.com"
```
### 2、库的创建与管理
```
$ git init  # 初始化一个库
```
工作区：项目目录  
暂存区：放置修改后的文件的位置  
版本库（.git）：提交修改文件的位置
```
$ git log  # 查看日志
$ git reset --hard 版本哈希值前五位  # 版本回退
$ git status  # 查看暂存区状态
$ git add 文件  # 添加更改至暂存区
$ git commit -m ""  # 提交修改到分支
```
当短时间内存在多次修改时，可以先不提交到分支，先提交至暂存区，这样后续再提交就会和上次修改合并。
```
$ git checkout --文件名  # 撤销修改，让修改回到最近git commit或者git add的状态

$ git rm 文件名  # 删除文件，当删除文件时，git status弹出提示后使用
```
### 3、远程库的创建与关联
登录GitHub创建新的仓库并勾选`Initialize this repository with a README`  
```
$ git clone  # 克隆到本地
```
### 4、分支管理
分支，用于多人协同工作时，想要添加新模块，但不想对团队共同的项目做更改时
```
$ git checkout -b 分支名  # 创建并切换（-b）分支
$ git checkout  # 切换分支
$ git branch  # 查看当前分支
$ git merge 分支名  # 合并指定分支到当前分支
```
当Git无法自动合并分支时，就必须首先解决冲突。
```
# 有些时候可能会遇到暂存区有修改，但是需要提交某分支上的修改到仓库中，可以用到：
$ git stash  # 把当前的工作现场（工作区和暂存区）储藏起来，让当前目录恢复到干净的状态。处理完其他分支的任务后，再通过 git stash pop 恢复现场，继续修改、添加和提交
$ git stash apply  # 恢复但不删除stash内容
$ git stash drop  # 删除stash内容
$ git stash pop  # 恢复并删除stash内容
$ git stash list  # 查看stash记录
$ git cherry-pick 提交哈希值  # 复制某个特定提交到当前分支
```
### 5、多人协作
```
$ git remote  # 查看远程库信息
$ git push origin master  # 推送分支上的提交到远程库
$ git pull  # 抓取分支
```
### 6、标签的创建与操作
```
$ git tag 标签名  # 切换到分支后创建标签（-a指定标签名 -m指定说明文字 -d删除标签）
$ git tag  # 查看所有标签
$ git log --pretty=oneline --abbrev-commit  # 查看commit id
$ git tag 标签名 commit_id  # 给指定修改打标签
```
```
$ git push origin 标签名  # 推送标签到远程仓库
```
