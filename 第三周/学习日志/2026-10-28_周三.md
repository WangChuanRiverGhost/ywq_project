# 装饰器的嵌套
设以下函数：
```python
def a(text):
    print(f"这是第一层嵌套：{text}")
    def b(func):
        print(f"这是第二层嵌套：{text}")
        def c():
            print(f"这是第三层嵌套：{text}")
            func()
        return c
    
    return b

@a("你好")
def print_aaa():
    print(f"这是被装饰的函数,函数名：{print_aaa.__name__}")

print_aaa()
```
在这个过程中，从程序运行的角度讲，存在两个东西：  
1、@语法糖后的装饰器  
可以注意到，我们在装饰器中传入了一个参数，换句话讲，这个装饰器实际上并非函数a，而是传入参数后被计算返回的结果【函数b】。所以实际上`@a("你好")`等同于`@b()`，python会将`print_aaa`作为参数传入`b(func)`（即b(print_aaa)）。  
2、被装饰的函数  
函数`print_aaa`被传入`b(func)`后，遵循非嵌套装饰器的规则，被`c()`接收并装饰，最终返回的结果是【函数c】。  
输出：
```text
这是第一层嵌套：你好
这是第二层嵌套：你好
这是第三层嵌套：你好
这是被装饰的函数,函数名：c
```
需要注意的是，@不只是声明，同时也会执行@中的语句。  
当更多层嵌套存在时同理，最内层的函数是包装的函数，最外层的函数接收参数，中间的函数传入和返回函数，最终获得倒数第二层函数。  
在上述例子中，即使不调用print_aaa()也会输出结果：
```text
这是第一层嵌套：你好
这是第二层嵌套：你好
```
# functools.wraps
在上述例子中可以看到，`print_aaa.__name__`被返回了c，但我们期望返回的是print_aaa。  
导致这种情况的原因是，print_aaa函数经过装饰后返回了c函数，所以拿到的函数属性也是c函数的属性而非被装饰前的print_aaa函数的函数属性。  
此时，为了让被装饰前的函数print_aaa函数属性不改变，可以使用functools.wraps：
```python
import functools
def a(text):
    print(f"这是第一层嵌套：{text}")
    def b(func):
        print(f"这是第二层嵌套：{text}")
        @functools.wraps(func)
        def c():
            print(f"这是第三层嵌套：{text}")
            func()
        return c
    
    return b

@a("你好")
def print_aaa():
    print(f"这是被装饰的函数,函数名：{print_aaa.__name__}")

print_aaa()
```
输出：
```text
这是第一层嵌套：你好
这是第二层嵌套：你好
这是第三层嵌套：你好
这是被装饰的函数,函数名：print_aaa
```
由于实际添加装饰以及最终实际返回的函数是最内层函数，所以`@functools.wraps(func)`写在它之前。
