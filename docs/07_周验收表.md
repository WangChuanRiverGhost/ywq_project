---

## 二、每周一巡检流程（10 分钟）

1. `git log --since="7 days ago" --pretty=format:"%ad %s" --date=short` 看提交分布
2. 对照上周计划，核对"实际完成天数"
3. 抽查 2 个代码文件：能否运行、命名是否合规
4. 填验收表，把"本周硬伤"和学生任务单选出来发给学生
5. 如果连续 2 周落后 → 触发排期重排（压缩非核心任务，保项目主线）

---

## 三、落后处理规则

| 落后程度 | 处理方式 |
|---|---|
| 落后 ≤1 天 | 学生自行用周末补齐 |
| 落后 2—3 天 | 压缩当周非核心内容（工具类、拓展类先砍），保项目主线 |
| 落后 ≥4 天 | 重排剩余周计划，砍掉可选内容（如 JWT、Docker 进阶），只保"最低可就业清单" |

**任何时候优先保的：** 项目能跑通 + 能部署 + 简历能写 + 能面试讲清楚。

## 五、课程变更记录（老师侧）

> 记录每周相对最初版教学计划的新增/改动。学生版周计划不含本节内容，避免学生困惑。

### 第 7 周变更（11/23—11/29）

1. **MySQL 全面替换 SQLite**：第 7 周起数据层统一用 MySQL，简历技术栈写"MySQL"而不是"SQLite"。
2. **SQLAlchemy ORM 完整闭环**：engine → Session → Base → Model → CRUD 函数，一条链路走完。
3. **数据持久化验证**：要求重启服务后数据不丢，用 Navicat 交叉验证。
4. **Charles / Fiddler 抓包实战**：抓自己项目的 POST 请求，并与数据库数据对照。
5. **测试用例设计方法**：等价类划分 + 场景法，落到注册/登录接口。
6. **项目 README 同步 MySQL 技术栈**：保证文档与代码一致。
7. **排期压缩**：因第 6 周收尾延后，day28+29 合并至 11/25，day33 并入 11/29，周日晚间复盘。

### 第 8 周变更（11/30—12/6）

1. **爬虫必须抓真实网站**：练习站只能用于过渡，最终项目素材必须来自真实公开网站。
2. **数据入库必须去重**：用数据库唯一约束实现，第二次运行 `inserted = 0`，面试可讲。
3. **爬虫产品化**：不停留在脚本，提供 `/crawler/run` 和 `/crawler/items` 接口，成为项目的一个模块。
4. **一键启动**：新增 `run.py` + `start.bat`，为第 11 周部署打底。
5. **配置剥离**：数据库连接信息进 `.env`，仓库只提交 `.env.example`。
6. **交付自测**：按 README 从零跑一遍项目，作为周六的验收方式。
7. **周前置检查**：周一先清第 7 周欠账，避免数据库没通就开工。
8. **降级方案**：三级降级，优先级固定为"项目能跑通 > README 完整 > 数据入 MySQL > 爬虫接口化"。
