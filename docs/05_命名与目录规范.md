# 命名与目录规范

> 本规范自第 7 周起强制执行。存量文件由老师统一整理，增量文件由学生自行遵守。

---

## 一、周目录

```
第N周/                          # 中文数字，不带空格：第一周、第七周
├── 第N周学习计划_学生版.md      # 阿拉伯数字：第7周学习计划_学生版.md
├── 学习日志/
└── 作业代码/
```

- 周目录用中文数字（`第一周`），计划文件名用阿拉伯数字（`第7周…`）——这是既有约定，保持不动。
- 周目录下只允许这三个子项，不允许把 `.py`、`.png` 直接扔在周根目录。

---

## 二、学习日志

**格式：`YYYY-MM-DD_周X.md`**

```
✅ 2026-11-25_周三.md
❌ 2026-11-25.md          （缺周几）
❌ 11-25学习日志.md        （缺年份、命名不统一）
```

周末也要写，可以短（3—5 行），但不能缺。

---

## 三、作业代码

**格式：`YYYY-MM-DD_dayXX_主题.py`**

```
✅ 2026-11-10_day18_http.py
✅ 2026-11-16_day22_pydantic.py
❌ a                                    （无意义文件名、无扩展名）
❌ a2026_11_11_day19_fastapi_hello.py   （多余的 a 前缀）
❌ 11_19_测试.py                         （空文件，禁止提交）
❌ 新建文件.py                            （无意义名称）
```

文件名 = 日期 + 课程统一编号 + 主题。日期用 `YYYY-MM-DD`；`dayXX` 是课程进度编号（day1—day100），不是日期。
- 一个知识点一个文件；同一天多个练习可加后缀：`2026-11-26_day31_crud_user.py`、`2026-11-26_day31_crud_todo.py`。
- 不允许提交 0 字节文件。

---

## 四、测试思维 / 面试题自测

**位置：`第N周/作业代码/测试思维.md`、`第N周/作业代码/面试题自测.md`**

- 每周一份，**追加写入**，不要把每天的答案拆成多个文件。
- 之所以放在 `作业代码/` 而不是单独 `笔记/`：第 1—4 周计划里已固定写为"追加到 `测试思维.md`"，为保持前后一致，沿用该位置，不再迁移。

---

## 五、截图与附件

- 位置：`第N周/作业代码/`
- 命名：`dayXX_说明.png`，例如 `day20_swagger.png`、`day26_注册成功图.png`
- 禁止 `1.png`、`截图.png`、`新建文件夹/` 这类命名。

---

## 六、项目目录

```
项目/用户管理系统/          # 根级，唯一位置
├── main.py
├── routers/
├── schemas/
├── models/                # 第 7 周起
├── database.py            # 第 7 周起
├── requirements.txt
├── postman/               # Postman Collection 导出的 .json（第 6 周起）
└── README.md              # 必须全大写
```

规则：

1. **只有一个项目目录**，任何周都不再新建"用户管理项目2"之类的副本。
2. 项目的 README 文件名必须是 `README.md`，写错（如 `REMADE.md`）GitHub 首页不渲染。
3. `requirements.txt` 必须由 `pip freeze > requirements.txt` 生成，禁止 0 字节。
4. 接口测试产物（Postman/Apifox 导出）放 `postman/`，不要只留截图。

---

## 七、禁止清单

| 禁止 | 正确做法 |
|---|---|
| 提交空文件 | 删除，或写完整再提交 |
| 一个文件塞多个不相关知识点 | 拆成 `dayXX_主题.py` |
| 在周目录根下散放代码/图片 | 归入 `作业代码/` |
| 文件名带 `a`、`新建`、`测试测试` 等前缀 | 用规范格式 |
| 项目在多处各存一份 | 只保留 `项目/用户管理系统/` |
| 提交 `__pycache__`、`venv`、`.db`、`.env` | 已在 .gitignore 中忽略，勿强加 |
