# pdb断点调试
```text
断点：当程序运行到有断点的地方的时候，先暂停运行
```
## 一、断点插入
插入一个断点，意味着在这里做一个标记，当我们决定调试时（无论是用调试工具还是命令行），跑到标记处才会停下来。日常运行程序时，除非插入的断点附加一些其他的功能（如pdb跑到断点位置会进入调试，即硬断点），否则不会暂停程序的运行。  
在pdb中，有以下三种插入断点的方式：
```python
breakpoint()  # 默认进入pdb，但由于调用时会查找环境变量PYTHONBREAKPOINT，可以通过更改的方式进入其他调试器

import pdb
pdb.set_trace()  # 直接进入pdb

await pdb.set_trace_async()  # (异步代码中)直接进入pdb
```
## 二、在python交互式环境中进行调试
### 1、单独调试一小段代码：pdb.run(目标代码)
在此之前，需要先进入python交互式环境：
```python
python
```
再使用pdb.run( )，即可进入pdb调试：
```python
>>> import pdb; pdb.run("x = [i**2 for i in range(100) if i % 3 == 0]")
> <string>(1)<module>()
(Pdb) 
```
### 2、测试一个函数在传入不同参数下的运行情况：pdb.runcall(function,*args)
### 3、针对返回值的表达式测试：pdb.runeval( )

### 2、在python文件中的try...except...针对异常实例进行调试：pdb.post_mortem(err)
pdb.post_mortem可以针对异常实例err，保留实例状态并转入pdb进行调试：
```python
import pdb;

try:
    x = 1/0

except Exception as e:
    pdb.post_mortem(e)
```
运行结果：
```python
PS D:\实训\学习计划> & 'C:\Users\ghost\AppData\Local\Programs\Python\Python314\python.exe' 'd:/实训/学习计划/第四周/11-5_测试.py'
> d:\实训\学习计划\第四周\11-5_测试.py(4)<module>()
-> x = 1/0
(Pdb) 
```
这两种方式的区别在于，pdb.pm查询的是程序中未被try...except捕获的异常，pdb.post_mortem查询的是程序中被手动捕获的异常。
## 四、进入pdb
基本命令结构：
```cmd
python -m pdb [pdb参数] (运行代码路径) [传给代码的参数]
```
其中，关于pdb参数：
```python
-c  # 后面跟命令，进pdb后自动执行
-m  # 后面跟调试目标（模块或包）
-p  / --   # 后面跟进程号，对该进程进行调试
```
## 五、配置pdb
可以对pdb进行配置使其个性化：
```python
import pdb

my_pdb = pdb.Pdb(skip=["第三方库.*"], colorize=True)  # 定制一个调试器
my_pdb.set_trace()  # 替换默认调试器
```
关于其中的参数：
```python
skip=["第三方库.*"]  # 屏蔽第三方库的代码
colorize=True  # pdb高亮显示
```

## 七、pdb操作指令
以下是一部分常用的pdb操作指令：
```python
n  # 执行当前行并停在下一行
s  # 执行当前行。如果当前行是一个函数调用则进入这个函数的内部
c  # 让程序往下跑，直到遇到下一个断点或者程序结束
q  # 退出调试

l  # 默认打印出当前停止行周围（11行）源代码，并在当前行前标箭头
p  # 打印变量
pp  # 格式化打印变量
```
