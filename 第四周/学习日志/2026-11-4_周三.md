# logging模块
### 关于logging的简述
logging是一个模块，用于对不同的情况做日志区分和内容。  
其核心在于日志对象LogRecord（是一个实例对象），运作在其基础上展开。  
围绕LogRecord，大抵经历了生成->筛选->再筛选->格式化LogRecord->输出LogRecord这几个环节，在实际操作中，我们做的是对生成、筛选、格式化、输出这几个环节的配置。  
### 关于logging的组成
1、日志对象LogRecord：整个过程中面向的对象；   
2、记录器Logger：初次筛选日志对象级别，生成日志对象LogRecord，并且对日志对象进行进一步的操作和筛选（如有）；  
3、处理器Handler：二次筛选日志对象级别，并且对日志对象进行进一步的操作和筛选（如有）；  
4、过滤器Filter：在记录器和处理器中对日志对象做进一步的操作和筛选；  
5、格式器Formatter：格式化日志对象，使其成为最终可以进行输出的期望文本格式
### 关于logging的过程
指定日志级别和内容->  
记录器两次筛选（分别是级别筛选【需要配置记录器级别】和过滤器筛选【需要配置过滤器】）->  
处理器两次筛选（分别是级别筛选【需要配置记录器级别】和过滤器筛选【需要配置过滤器】）以及向上传递【需要配置是否向父级传递】->  
格式器格式化最终的输出格式【需要配置格式器】->  
发送到指定位置（发送到哪里由不同的处理器及其配置决定）【需要配置处理器的输出目标】  
但是实际上这只是一个极度抽象的模型。在实际中，因为emit( )发射方法的不同，所以流程也会有所不同，同样这也是在【处理器的创建】中被提到的部分。  
其中，在处理器的筛选中，第一次的级别筛选是为了将日志传入不同的处理器（如果有多个处理器）。  
### 关于logging的配置
#### 首先，需要先创建一个日志记录器，这样做的目的是获取一个记录器对象。  
其中，`__name__`属性是为了标识日志的来源。当多个文件（2个及以上）该属性相同时，会返回相同的记录器对象。（即两个文件都定义了logger = logging.getLogger(aa.py)，实际上指向的是同一个记录器对象）  
从工程的角度讲，通常来说，我们使用文件的`__name__`属性进行创建，可以看到或直接屏蔽某一模块的指定日志，但从技术的角度讲，也可以将某一模块的日志给到另一个模块，只需要修改`__name__`为期望加入日志的模块名即可  
虽然从技术角度讲可以实现，但如果想要共用配置，需要用到下一趴的logging配置部分，通过Handler的配置实现多文件配置共享
```python
import logging
logger = logging.getLogger(__name__)
```
#### 其次，需要再创建处理器对象。（并非只需要创建记录器和处理器，只是过滤器和格式器并不是大多数情况需要的，所以分别放在记录器和处理器的配置中）  
其中，可供创建的处理器有以下几类：  
__1、基础控制台与文件__  
StreamHandler（输出到流，默认是sys.stderr控制台），开发调试用；  
FileHandler（输出到文件中），储存运行结果；  
```python
aa = StreamHandler(stream=None) # 通常没有参数，或传入sys.stdout
bb = FileHandler(filename, mode='a', encoding=None) # 文件名必须传，mode中，a是追加w是覆盖
```
__2、文件轮换（本质是FileHandler的进阶版）__  
RotatingFileHandler（文件超过设定大小，自动改名并新建），防止日志文件撑爆服务器硬盘；  
TimedRotatingFileHandler（定时生成新文件），按天或小时切分日志。
```python
cc = RotatingFileHandler(filename, maxBytes=0, backupCount=0) # maxBytes是文件大小，单位是比特；backupCount是保留天数
dd = TimedRotatingFileHandler(filename, when='h', interval=1, backupCount=0) # when是轮换单位（S/M/H/D/midnight/W0-W6/W）interval是间隔数量
```
__3、网络与系统级报警__  
SMTPHandler（通过smtp协议把日志以邮件形式发送），通常发送给开发人员；  
SocketHandler（将日志序列化后通过tcp发往远程机器），通常在架构中把分散的各机器中的日志集中发到日志中心服务器；  
SysLogHandler（将日志发给Unix/Linux系统底层的syslog守护进程）通常用于需要把python日志和系统日志统一管理。
```python
dd = SMTPHandler(mailhost, fromaddr, toaddrs, subject, credentials=None) # 服务器，发件人，收件人，标题，账密
ee = SocketHandler(host, port) # 远程机器ip和端口
ff = SysLogHandler(address=('localhost', 514)) # 地址和端口
```
__4、特殊用途__  
QueueHandler（把日志扔进队列后立刻返回，后台线程异步写入），用于高并发场景，防止主程序运行被卡；  
WatchedFileHandler（监视文件，如果发现文件被删了就重建一个接着写）；  
NullHandler（接收任何日志但不做任何操作）
```python
gg = QueueHandler(queue) # queue.Queue对象
hh = WatchedFileHandler(filename) # 文件名
ii = NullHandler()
```
除此之外，如有需要可以自定义创建一个处理器，只需要继承logging.Handler（或者它的子类）然后重写emit方法就可以
```python
class aaa(logging.Handler):
    def emit(self,record):
        pass
```
#### 之后，需要对记录器和处理器进行配置（配置它们的运行机制）  
##### 对于记录器来讲  
两个筛选过程：级别筛选和过滤器过滤；  
两个传递过程：把日志对象传送到处理器，以及向上传递处理后的日志对象  

共有四个配置点：记录器级别配置、记录器绑定过滤器（如有多个过滤器，且过滤器之间的执行有冲突时需要通过配置过滤器绑定顺序的方式决定过滤器的执行顺序）、记录器绑定处理器、单条日志是否向上传递  
其中，必要的配置是将处理器绑定给记录器。  
```python
logger.setLevel(logging.INFO) # 设置记录器的门槛级别

logger.addHandler(handler) # 给记录器绑定处理器
logger.removeHandler(handler) # 删除已绑定的处理器

logger.addFilter(filter) # 给记录器绑定过滤器
logger.removeFilter(filter) # 删除已绑定的过滤器

logger.propagete = True # 设置是否向上传递，True为是，False为否
```
##### 关于过滤器
以上出现了关于绑定过滤器的配置。但在绑定过滤器之前，需要先创建一个过滤器对象。创建一个过滤器对象有以下三种方法：
```python
# 创建一个包含filter的类
class myfilter:
    def filter(self,logrecord):
        return True

# 通过logging.Filter(def)创建
def aaa(logrecord):
    return True
logging.Filter(aaa)

# 直接在创建时传入一个可调用对象（包括普通函数或实现了__call__的类实例）
logger.addFilter(aaa)
```  
其中，关于过滤器有两点：  
第一，无论是以上哪种创建方式，过滤器的底层一定是一个函数对象，并且这个函数对象一定是一个返回了可以判断真假值的函数对象；  
第二，关于传入的logrecord参数，其本质是记录器创建的日志对象，对于日志对象可以操作的部分如下：
```python
record.msg # 传入的原始日志内容
record.getMessage # 日志纯文本内容
record.args # 格式化参数（日志内容中占位符的内容）
record.levelno # 日志级别的数字
record.levelname # 日志级别的名称
record.name # 记录器的名字
record.pathname # 产生该日志的python文件的绝对路径
record.lineno # 产生日志的代码行号
record.funcName # 产生日志的函数名
record.created # 日志创建的时间戳
record.exc_info # 异常信息（如有）
```
由于存在传入日志对象的特性，过滤器不止起到拦截的作用，同时也可以对传入的日志对象做深度加工（此时需要返回一个record对象来替换后续处理流程中的原对象，在3.12版本以上支持）：
```python
import logging,copy

class changeFilter(logging,Filter):

    def filter(self,record):

        new_record = copy.copy(record)
        new_record.msg = f"新增信息：{new_record.msg}"

        return new_record
```
当有多个过滤器对同一条日志对象进行处理时，只要有一个过滤器返回了False，这条日志对象就会被拦截。  
##### 对于单个处理器来讲（之所以是单个是因为一个记录器可以同时绑定多个处理器）
两个筛选过程：级别筛选和过滤器过滤；（其中，在一个记录器有多个处理器的情况下，级别筛选决定这个日志对象进入哪一个处理器）  
一个传递过程：把日志对象传递给格式器；  
一次输出过程：输出到输出对象。 

共有四个配置点：分别是单个处理器的级别配置、处理器绑定过滤器（如有多个过滤器，且过滤器之间的执行有冲突时需要通过配置过滤器绑定顺序的方式决定过滤器的执行顺序）、处理器绑定格式器、处理器绑定输出对象  
其中，必要的配置是输出对象（但实际上，这一点在进行处理器的创建时就进行了配置）。
```python
handler.setLevel() # 给处理器设置级别门槛

handler.setFormatter() # 给处理器选择一个Formatter对象

handler.addFilter() # 给处理器绑定一个过滤器对象
handler.removeFilter() # 删除一个已绑定在处理器上的过滤器对象
```
##### 关于格式器
以上出现了关于绑定格式器的配置。但在绑定格式器之前，需要先创建格式器对象。创建一个格式器对象使用以下方法：
```python
# 自己创建一个格式器
formatter = logging.Formatter.__init__(fmt=None,detefmt-None,style='%') # 消息格式字符串、日期格式字符串、占位符格式

# 关于占位符格式：'%'、'{'、'$'
aa = f"百分号占位符%(levelname)s" # 键名是record对象的属性
bb = f"括号占位符{levelname}"
cc = f"$占位符${levelname}"
```
格式器并不是刚需配置。当我们没有手动配置时，如果日志是一个字符串，会按照原字符串输出；如果日志是一个时间，则按照`%Y-%m-%d %H:%M:%S`的格式格式化（即年月日时分秒）。  
#### 以上的配置十分复杂，但并不是每次都需要配置所有部分，并且有简便配置的方法。
一定需要配置的三个配置点：记录器的创建与获取、记录器与处理器的绑定、处理器的输出目标，同样的，也需要创建处理器。  
而上述未提到的一定需要配置的部分，如过滤器和格式器，则在有需要时进行创建和配置。  

除此之外，存在一个“偷懒方法”进行配置：
```python
logging.basicConfig(filename='example.log', encoding='utf-8', level=logging.DEBUG)
```
该方法可以配置：

文件写入模式（filemode）：指定打开文件的模式，仅在提供 filename 时生效，默认为追加模式 'a'，也可设为覆盖模式 'w'。

日志格式（format）：指定日志输出的格式字符串，例如 '%(asctime)s - %(levelname)s - %(message)s'。

日期格式（datefmt）：指定 %(asctime)s 中日期时间的格式，遵循 time.strftime() 的规则。

根记录器级别（level）：设置根记录器的日志级别，低于该级别的日志会被忽略，例如 logging.INFO 或 logging.DEBUG。

输出流（stream）：指定一个流对象（如 sys.stdout）来创建 StreamHandler。若同时提供 filename 和 stream，stream 会被忽略。

处理器列表（handlers）：提供一个处理器可迭代对象并添加到根记录器。未设置格式器的处理器会使用默认格式器。

强制重配（force）：设为 True 时，会在配置前移除并关闭根记录器上已存在的所有处理器，允许重复调用 basicConfig() 重新配置。

文件编码（encoding）：指定日志文件的编码，仅在提供 filename 时生效。

错误处理（errors）：指定编码错误的处理方式，仅在提供 filename 时生效。

附加属性（extra）：传入一个字典，用于向日志事件的 LogRecord 注入自定义属性。

### 关于logging的使用
大体上讲，在使用时，logging有两个组成部分：日志级别和日志内容。  
##### 其中，关于日志级别（共5种）：  
DEBUG 用于调试，10； 
INFO 用于给运维或系统监控查看，说明程序正常运行，20；  
WARNING 用于程序还可以正常运行，但概率会出问题，或者未来会出问题的情况，30；  
ERROR 用于程序出问题，但整体没有瘫痪的情况，40；  
CRITICAL 用于程序已经彻底瘫痪，或者面临极其严重的安全问题，50
##### 关于日志内容
日志内容可以是任意对象。大体上可以分为字符串对象和非字符串对象。  
对于字符串对象：  
可以是纯字符串，或者带占位符的占位符字符串，或者F-string（但有时会有轻微性能损耗）  
对于非字符串对象：  
如数字、列表、字典、类实例等，会用str( )将其转换成字符串。  

使用方式：
```python
logger.info("这是一个调试日志")

aaa = "a"
logger.info("aaa的值%s",a)
```
##### 关于其他使用方式：错误与自定义级别
在日志级别中提到了error级别，有一个函数`Logger.exception()`也可以创建与其相似的日志信息，不过这个函数同时还可以记录堆栈追踪。  
但是，`Logger.exception()`只能在异常处理的except中进行使用。  
```python
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("aaa")

try:
    result = 1/0
except:
    logger.exception("出现了错误")
```
以上代码的运行结果：
```text
ERROR:aaa:出现了错误
Traceback (most recent call last):
  File "d:\实训\学习计划\第四周\11-4_测试.py", line 7, in <module>
    result = 1/0
             ~^~
ZeroDivisionError: division by zero
```
除此以外，还可以自定义日志级别：
```python
import logging

TRACE_LEVEL = 5 # 定义级别
logging.addLevelName(TRACE_LEVEL, "TRACE") # 注册级别

logger = logging.getLogger("aaa") # 创建记录器
logging.basicConfig(level=TRACE_LEVEL) # 配置记录器

logger.log(TRACE_LEVEL,"新增级别日志") # 根据级别值生成该级别的日志

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("aaa")
```
输出：
```text
TRACE:aaa:新增级别日志
```
以上的使用自定义级别的log方法是一个简单的使用方法，但如果期望像使用logger.info一样使用logger.trace，需要把该方法添加到Logger类：
```python
import logging

TRACE_LEVEL = 5  # 定义级别
logging.addLevelName(TRACE_LEVEL, "TRACE") # 注册级别

def trace(self, message, *args, **kwargs):

    if self.isEnabledFor(TRACE_LEVEL): # 判断当前的记录器是否允许输出这个级别
        self._log(TRACE_LEVEL, message, args, **kwargs)

logging.Logger.trace = trace # 将函数挂在类上并命名为trace
```
或者使用lamba：
```python
import logging

TRACE_LEVEL = 5 # 定义级别
logging.addLevelName(TRACE_LEVEL, "TRACE") # 注册级别

logger = logging.getLogger("aaa") #创建记录器对象
logger.TRACE = lambda msg, *args, **kwargs: logger.log(TRACE_LEVEL, msg, *args, **kwargs) # 写入方法，但需要在记录器实例对象上创建
```
