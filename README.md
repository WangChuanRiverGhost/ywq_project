# ywq_project — Python 实训仓库

> 16 周技术岗就业冲刺的学习轨迹仓库：学习计划、学习日志、每日作业代码、主线项目源码、接口测试用例，随进度逐步扩展。

## 目录结构

按周归档，每周一个目录，周内固定子目录；主线项目从第 6 周起独立到根级 `项目/`，后续各周只往里加代码，不再复制一份。

```
ywq_project/
├── README.md
├── docs/                       # 规范文档（入门、Git、命名、模板、验收）
├── 第一周/                      # 第 1—7 周同构
│   ├── 第N周学习计划_学生版.md
│   ├── 学习日志/                # YYYY-MM-DD_周X.md
│   └── 作业代码/                # dayXX_主题.py + 测试思维.md + 面试题自测.md
├── 第二周/ … 第七周/
└── 项目/                        # 第 6 周起的主线项目，唯一位置
    └── 用户管理系统/
        ├── main.py              # 应用入口
        ├── routers/             # 路由层（users.py / todos.py）
        ├── schemas/             # Pydantic 模型层
        ├── models/              # 数据库模型层（第 7 周起）
        ├── database.py          # 数据库连接（第 7 周起）
        ├── requirements.txt
        └── README.md
```

第 11 周部署阶段新增 `部署/`；第 12 周求职阶段新增 `求职材料/`。

> 命名规则见 [docs/05_命名与目录规范.md](docs/05_命名与目录规范.md)。**项目只有一处**：所有接口代码都写在 `项目/用户管理系统/`，不要在各周目录里另建项目副本。

## 提交规范

格式：`类型: 第N周 内容简述`

| 类型 | 含义 |
|---|---|
| `feat` | 新作业 / 新代码 / 项目功能 |
| `log` | 学习日志 |
| `plan` | 学习计划 |
| `fix` | 修改订正 |
| `docs` | 文档 |

示例：`feat: 第6周 day24 用户注册模块`

## 每日提交节奏

每天学完当天提交，**不许攒几天一起补**：

```
git pull  →  放文件  →  git add .  →  git commit -m "..."  →  git push
```

详细步骤见 [docs/02_Git提交作业操作指引_学生版.md](docs/02_Git提交作业操作指引_学生版.md)。
